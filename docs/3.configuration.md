description: Every option of the DMS Database module and how it labels schemas, set in the project configuration.

---

All options are optional. They go in the `config` block of the `@antelopejs/dms-database` entry of `antelope.config.ts`. The module reads them when the backend loads it, so a change takes effect after a backend restart.

This example labels the connection and gives billing data and tenant schemas their own badges:

```ts fragment [antelope.config.ts]
"@antelopejs/dms-database": {
  source: { type: "package", package: "@antelopejs/dms-database", version: ">=0.3.1 <1.0.0" },
  config: {
    driverLabel: "MongoDB",
    schemaLabels: {
      billing: { label: "Billing", color: "success" },
      "tenant-*": { label: "Tenant data", color: "warning" },
    },
  },
},
```

These labels only describe the connection. They do not select a driver or create schemas.

## Options

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `driverLabel` | `string` | none, the connection card shows only when the connection was last checked | Name of the database shown on the Overview's connection card, before the last check time, such as `"MongoDB"`. The Database interface cannot discover the driver, so you supply it. |
| `schemaLabels` | `Record<string, { label: string; color?: Tone }>` | none, the built-in patterns apply | Labels and colours for schemas, keyed by exact schema ID or by a glob pattern that contains `*`. |

## Schema labels

A schema label is the coloured badge shown next to a schema in the pickers, cards and lists. The module resolves it in this order:

1. An entry of `schemaLabels` whose key equals the schema ID.
2. The first entry of `schemaLabels`, in key order, whose key contains `*` and matches the whole schema ID. A `*` matches any run of characters, including none.
3. A built-in pattern. A pattern matches an ID that is the prefix itself, or that starts with the prefix followed by `-` or `_`. Case does not matter. For example, `app_billing` and `App` match `app`, and `apple` does not.

A schema that matches none of the three has no label.

| Prefix | Label | Colour |
| --- | --- | --- |
| `app`, `application` | Application | `info` |
| `core` | Core | `primary` |
| `global` | Global | `neutral` |
| `staging` | Staging | `warning` |
| `review`, `reviews` | Reviews | `secondary` |
| `prod`, `production` | Production | `success` |

`color` takes a DMS tone: `primary`, `secondary`, `success`, `info`, `warning`, `error` or `neutral`.

::note
The module has no settings page. What users change, such as diagram layouts, notes and saved queries, is data that the module stores in its own `dms-database` schema.
::
