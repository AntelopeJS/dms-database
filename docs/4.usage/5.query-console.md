# Query console

The Query console (`/modules/database/query`) runs AQL, the query language of the AntelopeJS Database interface, against any registered schema.

![A query on demo.tags and its result table, with the history on the left](../images/query-result.png)

## Write and run

A query starts from `schemas.<schema>.instance(<id>?)` and chains the table operations of the Database interface:

```ts
schemas.shop.instance().table("products").orderBy("price").slice(0, 10)
```

- `Ctrl` `Space` completes schemas, tables and columns from your own workspace.
- The **Insert** chips add common operations: `table()`, `filter()`, `orderBy()`, `slice()`, `count()`, `get(id)`.
- **Format** tidies the query; `Ctrl` `Enter` runs it.
- An empty console offers two examples built on your own tables.

## Read the result

The result shows its row count, duration and target. Choose a view or export:

| View or export | Contents |
| --- | --- |
| **Table** | The rows returned by the console, up to 1,000. |
| **JSON** | The same returned rows, also available to copy. |
| **Chart** | The first numeric column in the returned rows. |
| **Export CSV** | The same returned rows, not the full database result. |

::note
The server returns at most 1,000 rows per run. If the result is truncated, switching views or exporting does not retrieve the missing rows. Narrow your query or read separate slices with a stable ordering when you need more data.
::

**Open in data browser** opens the target table.

## Writes are confirmed first

A query that inserts, updates, replaces or deletes never runs straight away:

1. The console runs a **dry run** first.
2. Review the operation, the target and the number of rows it would touch.
3. To confirm, type the table name.

::warning
Confirmation executes the write against the database. The dry run is a preview, not a rollback mechanism or a locked snapshot: data can change before you confirm. Check the target and filter, and back up important data before destructive operations.
::

![The confirmation dialog of a delete on demo.tags, after its dry run](../images/query-guard.png)

## History, saved and team queries

The library on the left has three tabs:

- **History**: your last 500 runs, grouped by day, searchable. **Clear history** empties it.
- **Saved**: the queries you saved (`Ctrl` `S`), with a name and a description.
- **Team**: the queries teammates shared. Teammates can run a shared query; only its author can edit or delete it.
