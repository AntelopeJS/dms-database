The module has no interface of its own to implement. It reads what the rest of the project already declares. This page lists what it picks up and how other modules use it.

## Supported extension boundary

The supported ways in are registered database schemas, the Table watch trigger, the configuration and the deep links on this page. The runtime's root barrel also re-exports its page and route classes. Those exports exist, but they are not an extension SDK and not a supported subclassing contract. Do not register those controllers again or depend on their implementation methods. Declare your own pages through `@antelopejs/interface-dms` and your tables through the database interfaces instead.

## Your tables appear on their own

Every schema registered through `@antelopejs/interface-database-decorators` appears in the console, with its tables, columns, indexes and relations. The console needs nothing more than the registration:

```ts docs-check
import { BasicDataModel, Field, Index, RegisterSchema, RegisterTable, Table } from "@antelopejs/interface-database-decorators";

@RegisterTable("posts", "blog")
export class Post extends Table {
  @Field("string") declare _id: string;
  @Index() @Field("string") declare title: string;
  @Field("string") declare author: string;
}

export class PostModel extends BasicDataModel(Post, "posts") {}

export async function start(): Promise<void> {
  await RegisterSchema("blog");
}
```

In a module, the table class lives in its own file, such as `src/db/posts.table.ts`. The module entry imports that file and calls `RegisterSchema("blog")` in its `start()` hook. `@Field` declares each column's storage type, and `@Index` alone does not declare a field. The instance pickers list each instance of the schema, the default one and each named one (one per tenant or per region, for example). Columns marked hashed, localized or encrypted carry a modifier badge.

::tip
[`schemaLabels`](/docs/modules/database/configuration#schema-labels) gives a schema a readable badge without a rename. Schema IDs are part of the stored data.
::

## Table watch automation trigger

When [`@antelopejs/dms-automation`](/docs/modules/automation/introduction) is loaded, the module registers the **Table watch** trigger (`database.table-watch`). The trigger fires a procedure on each insert, update or delete in a table of the default instance, read from the database change feed. Without the automation module, the registration is a no-op.

| Config | Type | Required | Description |
| --- | --- | --- | --- |
| `schema` | `string` | yes | Registered schema ID, such as `shop`. |
| `table` | `string` | yes | Table name inside the schema. |
| `eventTypes` | `("insert" \| "update" \| "delete")[]` | no | Change types to fire on, at least one. Omit it for all three. |

Activation fails with a `table-watch:` error when `schema` or `table` is empty, when the schema or the table is not registered, or when `eventTypes` is empty or holds another value.

Each event passes this output to the procedure:

| Field | Type | Description |
| --- | --- | --- |
| `type` | `"insert" \| "update" \| "delete"` | The change. |
| `old` | `object \| null` | The row before the change. It is `null` on insert, and may hold only the primary key when the store keeps no pre-image. |
| `new` | `object \| null` | The row after the change. It is `null` on delete. |
| `schema`, `table` | `string` | Where the change happened. |
| `at` | `string` (date-time) | When the module received the change. |

The rows are passed as JSON, so a date arrives as its ISO string.

::warning
The trigger needs a database with a change feed. MongoDB offers one only on a replica set. On a standalone server, activation fails with `table-watch: cannot open change feed on <schema>.<table>:` followed by the MongoDB error, "$changeStream is only supported on replica sets". The trigger runs on one node of a cluster only. After a feed error, it reconnects once, 5 seconds later, and stops with an error log if the feed fails again.
::

## Roles and components

Each block of the module's pages carries `.meta({ name, icon, description })`, which names it. The pages sit inside a DMS module, so they are reserved to the platform owner. The DMS registers no permission for a module page or its blocks, so the role editor does not list them and a role cannot grant them.

## Link to the console

The pages read their selection from the URL, so any page, notification or row action can link into the console:

| Link | Opens |
| --- | --- |
| `/modules/database/schemas?record=<schema>::<table>` | The table inspector |
| `/modules/database/diagram?schema=<schema>&table=<table>` | The diagram, centred on a table |
| `/modules/database/data?schema=<schema>&table=<table>` | The table in the data browser |
| `/modules/database/data?schema=<schema>&table=<table>&match=<column>:<value>` | The table in the data browser, filtered on one column value |
| `/modules/database/query?schema=<schema>&table=<table>` | The query console on that table |
| `/modules/database/query?history=<id>` | A run from the query history |
| `/modules/database/query?q=<id>` | A saved query |

On the Schemas, data browser and query console pages, add `instance=<name>` for a named instance, or `instance=all` for every instance. Without `instance`, a link opens the default instance.

## Frontend components

The module ships a Vue frontend module under the `DmsDatabase` component prefix. It registers every component of `frontend-vue/app/components`, and the module's pages mount these ones: `DmsDatabaseConnectionStatus`, `DmsDatabaseSchemasFilterBar`, `DmsDatabaseTableInspector`, `DmsDatabaseSchemaDiagram`, `DmsDatabaseDataBrowser` and `DmsDatabaseQueryConsole`. They are built for the module's own pages and read owner-only routes under `/api/database`. They are not a public API for other modules.

A server render waits for the data that sets a component's size, and a client navigation waits for it too, instead of a placeholder that the answer then resizes. That data is the Overview's connection probe and schema cards, and the query console's schemas and query library. On a return to a page, the components show the data read before at once and read it again in the background.
